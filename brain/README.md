# The brain

What the persona knows about the people it talks to, so it can recognise them
and pitch what it says accordingly.

## The idea

Discord already stores every message anyone has ever sent, permanently, for
free. A memory system that logged observations would be maintaining a worse
copy of a database that already exists. So the brain stores **only
conclusions**, and re-derives them from Discord whenever you ask it to.

That splits the work in two:

```
  LIVE BOT (bot.py)              OFFLINE TOOL (brain.py)
  ─────────────────              ───────────────────────
  reads profiles                 reads Discord history
  notes people it hasn't met  ──▶  writes/updates profiles
  writes no prose                you review before it goes live
  no added API cost              ~1 cheap call per person
```

The live bot never writes prose about anyone. The one thing it does is record
that it saw a user ID it doesn't recognise, which costs nothing and builds the
to-do list that the next scan works through.

Profiles are written offline, in batches, where the model reads hundreds of a
person's messages at once. This is the whole reason the output is usable: a
memory that updates itself live sees a 30-message keyhole, and what accumulates
from that is drift with nothing to catch it.

## Layout

```
brain/
├── README.md          this file                      [committed]
├── _index.json        user_id -> file, aliases       [gitignored]
└── people/                                           [gitignored]
    └── <handle>.md
```

Keyed on **Discord user ID**, never display name. Names change; if names were
the key, every profile would silently fork the day someone renamed themselves.

Contents are gitignored. These are notes about real people taken from a private
channel - the structure is public, what's in it isn't.

## Profile anatomy

```markdown
# Zack Kross (slaymakerlol)

## Who they are      ← regenerated by every scan
## How they type     ← regenerated
## Running bits      ← regenerated

<!-- HAND-WRITTEN BELOW - brain.py never regenerates past this line -->

## Jaq's read
Enemy and friend, in that order, and the order is the joke...
```

**That marker is the load-bearing part of the whole design.**

Everything above it is *observed* - cheap to re-derive, safe to throw away and
rebuild from a fresh scan. Everything below it is *authored*: how the persona
feels about this person, which grudges to run, what to never concede. No volume
of chat history implies any of that. It is a decision you made, and a scan
preserves it byte for byte.

## Using it

```bash
.venv/bin/python src/brain.py scan          # update from CHANNEL_ID
.venv/bin/python src/brain.py scan --channel 381547894525919262
.venv/bin/python src/brain.py scan --force  # redo everyone, ignore watermarks
.venv/bin/python src/brain.py list          # who's known, who's only been seen
```

A scan skips anyone below `BRAIN_MIN_MESSAGES`, because a confident profile
built on nine messages is worse than no profile. It also skips anyone who
hasn't said `BRAIN_MIN_NEW` new things since last time, so re-running it is
nearly free. Read what it wrote, then `./restart.sh`.

## What reaches the prompt

```
persona.md
  + brain rules ("inform, never recite")
  + core profiles      (BRAIN_CORE - always, however quiet they've been)
  + situational        (whoever is in the last HISTORY_LIMIT messages)
```

Capped at `BRAIN_MAX_PROFILES`. Loading everyone on every call would spend
tokens on absent people and spread the model's attention across a crowd; this
way cost is set by how many people are actually in the room, and the brain can
grow to any size without the per-reply cost moving.

Every injected block is prefixed with a standing rule: **the brain informs how
the persona behaves, and is never recited.** Without it, a bot handed dossiers
starts performing them - telling people what it knows about them, which is both
unfunny and a direct breach of the persona's own rule against disclosing
identifying details.

## Adding someone by hand

You don't need the tool. Drop a file in `people/`, add the user ID to
`_index.json`, done. The tool exists to save you writing the observational part
for the tenth person, not to own the format.
